OLLAMA-WEBUI - HOW THE PROJECT WORKS
====================================

WHAT IT IS
A chat web app for local Ollama models. The user picks a model, types a
prompt (optionally attaching files or screenshots), and the reply streams back.

FOLDERS (each has one job; calls only go frontend -> backend -> ollama)
  frontend/   index.html - the whole UI (HTML + CSS + JS in one file).
              Talks to the backend only through /api/* over HTTP.
  backend/    FastAPI app (Python). Receives HTTP requests, calls the
              ollama_pipeline package, and serves frontend/ at "/".
                app/main.py      creates the app, mounts the frontend
                app/routes.py    the API endpoints
                app/schemas.py   request shapes
                app/settings.py  HOST/PORT/CORS from env or backend/.env
  ollama/     The Ollama layer (installed into the backend as a package).
                config/models.yaml   Ollama servers + models in the picker
                config/themes.yaml   prompts for the "Today's Theme" chip
                config.local/        optional copy of config/ for this machine
                                     only (not in git, used when present)
                ollama_pipeline/client.py     raw HTTP calls to Ollama
                ollama_pipeline/registry.py   which models exist / are pulled
                ollama_pipeline/router.py     auto-routing: which model answers
                ollama_pipeline/opencode.py   cloud answers via `opencode serve`
                ollama_pipeline/pipeline.py   builds messages, streams reply
                ollama_pipeline/documents.py  PDF/DOCX/text -> plain text
  run.sh      starts the backend on http://127.0.0.1:8000
  run.ps1     the same for Windows PowerShell

REQUEST FLOW
  1. Page loads -> GET /api/models -> registry asks each Ollama host
     (/api/tags) what is pulled -> model list shown in the picker.
  2. User attaches a file -> POST /api/files -> documents.py extracts text.
     Images stay in the browser as base64.
  3. User sends -> POST /api/chat {model, messages}
     -> if model is "auto", the router picks a model (see AUTO-ROUTING)
     -> registry resolves the model -> pipeline adds the system prompt,
        folds file text into the message -> Ollama /api/chat (streaming)
     -> backend streams NDJSON lines back:
        route / notice / thinking / delta / done / error
     -> frontend renders the reply as it arrives: reasoning in a live
        "Thinking..." block, then the answer text with a caret while it grows.
  Other endpoints: GET /api/health, GET /api/theme. API docs: /docs

AUTO-ROUTING ("Auto" in the model picker, the default when enabled)
  Runs before every reply, in ollama_pipeline/router.py, configured under
  `router:` in ollama/config/models.yaml. Each route = a description + a model.
  Order of decision for the latest user message:
    1. Has an image            -> router.image_model (vision model)
    2. A software question in a chat with nothing attached -> a cloud route,
       when one is configured: "expert" for system design and hard-to-find
       bugs, "code" for the rest. It is recognised by clear signs (a language
       name, a code snippet, pasted commands, "fix this bug", "code this",
       "build a website"), or by the chat already being about software: the
       request before it was a software one, or the last reply has code in
       it ("add error handling to it"). A request for an email, a translation
       or a summary does not follow the thread and stays local. This is
       checked first, so a local reply never holds later code questions back.
       If the chat has attachments the question stays local and the reply
       says why.
    3. A short follow-up ("make it shorter") stays on the local model already
       answering. When Von is installed it can also send software the signs
       above missed to the cloud, by answering yes to two questions about it
    4. Von is installed and its confidence >= min_confidence -> Von's choice
       between the local routes. Von unsure -> stays on the model already
       answering, if that is a local one
    5. Otherwise: keyword rules (code/logic/maths/long/attached file -> heavy
       route, everything else -> default route)
  Each decision is one line in the server log ("Router: ...").
  A route can list several models; the first that can answer is used.
  If the chosen model is not pulled, another routed model is used instead.
  Von missing, loading, failing or slow never blocks a chat: rules take over.
  Von (optional, https://github.com/wfzyx/von): a 395M decision model, CPU,
  English only, ~3 GB download. Enable with:
        cd backend && uv sync --extra router      (needs Python 3.12+)
  Without it, set `backend: rules` or just leave it - rules are the fallback.
  Picking a specific model in the picker bypasses routing completely.

OPENCODE (cloud routes, optional)
  The "code" route sends questions about software, and the "expert" route the
  hardest of them - architecture, system design, hard debugging - to
  OpenCode's free cloud models (https://github.com/anomalyco/opencode).
  Everything else stays on the local models. The backend starts its own
  password-protected `opencode serve` on 127.0.0.1 and streams replies from
  it. Needs OpenCode 1.x installed. Config: `opencode:`, the `opencode*`
  models and the two routes in models.yaml; remove `code_route` and
  `expert_route` to stay fully local.
  - These messages LEAVE THIS MACHINE. Attachments are never sent, and a
    conversation that has had an attachment stays on local models.
  - OpenCode runs in an empty temp folder; every request it makes to run a
    command, edit a file, fetch a URL or read elsewhere is rejected.
  - The free tier only works with OpenCode's built-in agent, unmodified.
  - If a model does not answer, the next one in its route does; after the
    last, or if OpenCode is missing, the local heavy model. The reply says so.
  - The free models differ in what their providers do with prompts; see the
    comment above them in models.yaml.
  - The reply streams live; the first words usually take 5-10 s.

DOCUMENTS
  PDF/DOCX/text are converted to text and placed in the prompt. The model
  only reads `num_ctx` tokens (default_options in models.yaml, 16384 here;
  Ollama's own default is ~4096 and silently cuts long documents). A warning
  appears in the reply when a conversation is larger than num_ctx.
  What does not fit is dropped from the start, so the model then answers
  from the end of the document or chat only.
  Scanned PDFs contain no text: send screenshots to a vision model instead.

REQUIREMENTS
  - macOS, Linux or Windows
  - Python 3.11+ and uv (https://docs.astral.sh/uv/), or pip with
    requirements.txt. The Von router needs Python 3.12+.
  - For the cloud routes: Node.js and OpenCode 1.18.34
        npm install -g opencode-ai@1.18.34       (2.x does not work)
  - Ollama (https://ollama.com/download), running, with at least one model:
        ollama pull llama3.2:3b
  - Internet for the background video and Inter font (frontend loads them)

RUN
  ./run.sh            then open http://127.0.0.1:8000
  Windows: powershell -ExecutionPolicy Bypass -File run.ps1
  If it says the port is in use, the app is already running.
  After changing backend/ or ollama/ code: Ctrl+C and ./run.sh again.
  After changing frontend/: just refresh the browser.

HOW TO MODIFY
  Add/rename a model, system prompt, or Ollama server -> ollama/config/models.yaml
  Different models on one machine only                -> copy ollama/config to ollama/config.local
  Change which model handles which kind of request    -> `router:` in models.yaml
  Change routing logic / keyword rules                -> ollama_pipeline/router.py
  Let the model read longer documents                 -> default_options.num_ctx in models.yaml
  Change daily prompts                                -> ollama/config/themes.yaml
  Change how prompts are built (RAG, tools, logging)  -> ollama_pipeline/pipeline.py
  Support a new file type                             -> ollama_pipeline/documents.py
  Add an API endpoint                                 -> backend/app/routes.py
  Change port/host                                    -> backend/.env (copy .env.example)
  Change the UI                                       -> frontend/index.html
  New Python dependency: add to the right pyproject.toml, then `cd backend && uv sync`.

NOT BUILT YET
  No login, no saved chat history, scanned PDFs have no text, Figma links
  are passed as text only. Paid cloud models (e.g. Claude) are not
  built: it would be one more provider next to opencode.py.
